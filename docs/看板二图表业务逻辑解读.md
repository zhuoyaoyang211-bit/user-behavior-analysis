# 看板二 · 每张图背后的业务逻辑解读

> 数据口径：测试集 test.parquet，468,316 对（正样本 449，正样本率 0.096%）；最终模型 XGBoost Optuna，阈值 0.2

## 先说结论：整个看板二在讲一个什么故事

看板二是"模型评估看板"

| 模块 | 回答的业务问题 | 类比 |
|---|---|---|
| 模块一 | 这模型到底行不行？凭什么选它？ | **成绩单** |
| 模块二 | 它在各种"考法"下表现稳不稳？ | **体检报告** |
| 模块三 | 它对哪类人/哪类商品/哪个时间段特别好或特别差？ | **分人群体检** |
| 模块四 | 它做决策的依据是什么？可信吗？ | **让模型自述理由** |
| 模块五 | 它错在哪儿？错得有没有规律？还能不能改进？ | **认错与复盘** |

一句话串起来：**模型不是"跑完就完"，要证明它能用、好用、知道它为什么好、也知道它哪里不好——这才是一个能给业务交付的模型。**

# 模块一 · 成绩单：模型核心指标概览

## 1.1 八张指标卡

### 怎么读图

| 卡片 | 业务含义 | 当前值 | 怎么算的 |
|---|---|---|---|
| ROC-AUC | **排序能力**：随机抽一个"真买的人"和一个"真没买的人"，模型有多大把握把前者排到后面 | 0.9942 | 所有 (用户,商品) 对的概率排名质量 |
| PR-AUC(AP) | **极不平衡场景的主指标**：在正样本只有 0.096% 的情况下，模型把"购买"从海量噪音里捞出来的能力 | 0.1312 | 精确率-召回率曲线下面积 |
| LogLoss | **概率质量**：预测的"购买概率"数字本身靠不靠谱（越低越好） | 0.0052 | 每个样本预测概率与真实标签的交叉熵 |
| 当前阈值 | **业务开关**：概率超过多少才判定为"会买" | 0.2 | 内部调优验证集选定 |
| 准确率 | 全部预测中猜对的比例 | 99.59% | (TP+TN)/总数 |
| 精确率 | 预测"会买"的里面，真买的比例 | 11.81% | TP/(TP+FP) |
| 召回率 | 真买的人里，被模型逮到的比例 | 51.22% | TP/(TP+FN) |
| F1 | 精确率与召回率的调和平均 | 0.1920 | 2PR/(P+R) |

### 背后的算法逻辑（重点）

**为什么正样本率 0.096% 时，准确率 99.59% 毫无意义？**

如果模型"全都预测不买"，准确率 = 99.90%（因为 99.9% 的人本来就不买），比模型的 99.59% 还高！**准确率被"绝大多数都是负样本"这个事实绑架了**，所以这里真正要看的不是准确率，而是：

- **ROC-AUC 0.9942** 说明模型能把真买家排到前面（排序能力强）
- **PR-AUC 0.1312** 是"捞购买"能力的真实体现——随机瞎猜只有 0.096%，模型是它的 **137 倍**
- **精确率 11.81%**：意味着你推 100 个"可能购买"的商品，约 12 个真会买——比随机推（不到 1 个）强 12 倍

**为什么精确率看起来还是很低？** 因为业务上"会买的人"本来就极稀少（千分之一）。任何模型在这种数据上都面临同样的天花板，所以**业务上不能指望"精确率 50%"，而是要靠排序把购买集中在头部（见模块三 Top-K）**。

## 1.2 多模型横向对比图（双柱状图 + 表格）

### 这张图回答什么业务问题

"**你说你的模型好，跟别的方案比过没有？**" 这张图是**选型依据**——15+ 个候选方案同台竞技，证明"我选的 XGBoost Optuna 不是拍脑袋，是比出来的"。

### 怎么读图

- 左图：ROC-AUC（排序能力）——传统 ML 和 Tree 融合都 0.98+，序列模型和 DIN 融合明显掉下去
- 右图：PR-AUC（不平衡主指标）——**差距真正拉开**，选型看这张
- 颜色按阶段分组：蓝色=基线、绿色=Optuna、紫色=Tree 融合、橙色=DIN+Tree、棕色=XGB+DIN、红色★=最终模型测试集泛化

### 背后的算法逻辑

**为什么同一批模型，要分"验证集"和"测试集"两个口径？**

- 验证集成绩：各模型在**同一份数据**（val，93.6 万对）上公平 PK，用于选型
- 测试集成绩：最终模型在**从未参与任何调参**的 test 上跑一次，用于证明"没作弊"

**候选方案都代表什么业务思路？**

| 阶段 | 方案 | 思路 | 验证集 PR-AUC | 关键结论 |
|---|---|---|---|---|
| 步骤六基线 | 逻辑回归 | 最传统的线性模型 | 0.0703 | 线性拟合不了复杂行为关系 |
| 步骤六基线 | LightGBM / XGBoost | 树模型默认参数 | 0.1249 / 0.1248 | 树模型大幅领先线性 |
| 步骤六基线 | GRU / LSTM / DIN | 深度序列模型 | 0.0036 / 0.0025 / 0.0045 | 数据量/特征下深度模型不占优 |
| 步骤七 Optuna | XGBoost Optuna ★ | 自动搜参 | **0.1560** | 调参有效，+25% |
| 步骤七 Optuna | LightGBM Optuna | 自动搜参 | 0.1050 | **调参反而变差**——超参敏感 |
| 步骤七 Tree 融合 | Tree 等权 | LGBM 0.5 + XGB 0.5 固定权重 | 0.1546 | 接近单模型 |
| 步骤七 Tree 融合 | OOF Stacking | 5 折 OOF + 二层 LR | 0.1529 | 概率校准更好，但 PR-AUC 略降 |
| 步骤七 DIN+Tree | DIN 等权 / 20% / 40% | 把 DIN 加入树模型融合 | 0.1235 / 0.1517 / 0.1068 | 最好的 DIN20% 仍未超过 XGBoost |
| 步骤七 XGB+DIN | XGB 95% + DIN 5% ~ 50% | 最强单模型 + DIN 概率加权 | 0.1542 → 0.0842 | DIN 权重越高，PR-AUC 越低 |
| 步骤九 | XGBoost Optuna（测试集） | 最终定版泛化 | 0.1312 | 相对验证集略降，无过拟合 |

### 当前数据的结论（四个值得讲的点）

1. **XGBoost Optuna 全场第一（0.1560）**，最终测试集 0.1312 只是略降，说明没有过拟合
2. **LightGBM 调参后反降**（0.1249→0.1050）——诚实素材：不是调了参就一定更好，**模型选择靠实验数据说话，不靠直觉**
3. **所有融合都没打过单模型**：Tree 等权 0.1546、OOF Stacking 0.1529、DIN20% 0.1517、XGB95%+DIN5% 0.1542——全都低于 XGBoost Optuna。说明在这个数据规模下，**增加复杂度没有带来收益，反而引入 DIN 的噪声**
4. **深度序列模型集体垫底**（GRU/LSTM/DIN 都在 0.005 以下）——不是深度学习不行，而是这个项目里用户-商品交互稀疏、序列短、统计特征强，树模型更匹配

### 业务含义

**"我们不是只跑了一个模型，而是从基线、调优、融合、深度学习四个方向做了 15+ 个方案横向 PK，最终用数据选出 XGBoost Optuna。"** 这句话本身就是汇报的加分项——体现的不是"会跑模型"，而是"会做减法、敢做减法"：不是模型越复杂越好，而是哪个方案在这个业务场景下最稳。

# 模块二 · 体检报告：整体性能深度评估

## 2.1 ROC 曲线 + PR 曲线

### 这张图回答什么业务问题

成绩单只给了 8 个"总分"，曲线则回答："**模型在所有'严格程度'下的表现，而不是只看某一个点。**" 

### 怎么读图

- **左图 ROC**：横轴=误报率（把没买的当买的），纵轴=命中率（真买的逮到多少）。**曲线越往左上角弯，越好**。灰色对角线=瞎猜
- **右图 PR**：横轴=召回率，纵轴=精确率。**曲线越往右上角弯，越好**。灰色横线=随机水平（0.096%）

### 背后的算法逻辑

**为什么两幅图都要看？**

ROC 有个著名的坑：**正负样本极端不平衡时，ROC 曲线会"过于乐观"**。因为 ROC 的横轴（FPR）分母是"没买的人"——这个分母有 46 万个，漏几个误报根本看不出来。而 PR 曲线的横轴是召回率、纵轴是精确率，**精确率的分母是"被预测为购买的人"——人本来就少，多一个误报立刻现形**。所以：

- ROC-AUC 0.9942 是"听起来很漂亮"的指标
- PR-AUC 0.1312 是"真实业务水平"的指标
- **两者要一起报**：只报 ROC 0.994 会被懂行的人追问"那 PR-AUC 呢？"

### 当前数据的结论

模型 ROC 曲线几乎贴满左上角（0.9942），说明"排序"做得极好；PR 曲线远高于随机横线但绝对值不高（0.1312）——**这是极不平衡场景的正常形态，不是模型坏了**。

### 业务含义

一句带过即可："**模型排序能力极强（ROC 0.994），在极稀疏购买场景下真实捞取能力为随机水平的 137 倍（PR-AUC 0.1312 vs 0.096%），业务上配合 Top-K 策略使用（见模块三）。**"

## 2.2 阈值敏感性分析

### 这张图回答什么业务问题

这是**整块看板里最"业务"的一张图**。它回答："**我们手里的'0.2'这个开关，拧到别的位置会怎样？**"

业务上，阈值直接对应两种"钱"：
- 阈值调低 → 推送给更多人 → **召回多（不漏单）但误报多（打扰用户、浪费营销预算）**
- 阈值调高 → 推送给更少的人 → **误报少但漏单多（错过真实买家）**

### 怎么读图

- 蓝线（精确率）：阈值越高越精确（只推最有把握的）
- 红线（召回率）：阈值越高召回越少（推得少自然逮得少）
- 绿线（F1）：精确率与召回率的"平衡点"
- 灰色虚线 = 当前阈值 0.2；绿色虚线 = 测试集上 F1 最高的点 0.45

### 背后的算法逻辑

阈值 = **业务严格程度**。0.2 的意思是"模型说你有 20% 概率会买，我就推给你"。当前数据：

| 阈值 | 精确率 | 召回率 | F1 | 业务效果 |
|---|---|---|---|---|
| **0.2（当前）** | 11.8% | **51.2%** | 0.192 | 捞得多：一半的买家都被逮到 |
| 0.45（F1 最优） | **16.6%** | 25.2% | 0.200 | 推得准：但只捞到 1/4 买家 |

**为什么当前选 0.2 而不是 F1 更高的 0.45？**

因为 F1 是"纯算法指标"，它把"漏掉一个买家"和"多打扰一个用户"看成同等代价。但**业务上两者代价完全不同**：漏掉一个真买家 = 丢失一单收入；多推一个不买的 = 只是一次打扰。所以业务倾向"多捞"（高召回），牺牲一点精确率——这就是 0.2 的由来。

### 业务含义

这张图是"防杠神器"：如果有人问"为什么精确率只有 11.8%？"——**"这是我们主动的选择：调高阈值能把精确率提到 16.6%，但会丢掉一半的买家；在'漏单损失 > 打扰成本'的业务假设下，我们选 0.2 追求高召回。"** 阈值是可调的旋钮，不是模型的缺陷。

## 2.3 归一化混淆矩阵（绝对数值 + 行归一化）

### 这张图回答什么业务问题

"模型到底错成什么样？" 混淆矩阵是**最诚实的账本**：四笔账一目了然——推对了多少、推错了多少、漏了多少、躲过了多少。

### 怎么读图

- 左图（绝对数值）：真实"未购买"被正确忽略 466,536 个（TN）、被误推 1,331 个（FP）；真实"购买"被漏掉 219 个（FN）、被逮到 230 个（TP）
- 右图（行归一化）：每一行按行求和=100%。**看"行"而不是看"列"**：
  - 真买的人那一行：51.2% 被逮到（TP），48.8% 被漏掉（FN）
  - 真没买的人那一行：99.7% 被正确忽略，0.3% 被误推

### 背后的算法逻辑

**为什么必须看"行归一化"版本？**

绝对数会骗人：FP=1,331 看着比 TP=230 大 6 倍，好像"误报很多"。但行归一化后真相是——**0.3% 的未购买者被误推，而 51.2% 的购买者被召回**。用比例说话，才能把"模型其实做得不错"这件事讲清楚。这是做不平衡分类汇报的必备技巧。

### 当前数据的结论

- 每 100 个真买家，模型逮到 51 个（还剩 49 个漏网，见模块五分析为什么漏）
- 每 1000 个不买的人，模型只打扰 3 个（绝大多数人不会被骚扰）

### 业务含义

**"模型的打扰率只有 0.3%，却覆盖了 51% 的购买行为"**——一句话既交代了准确率，又交代了覆盖率，是给业务方最有说服力的总结。

## 2.4 概率校准曲线（可靠性曲线）

### 这张图回答什么业务问题

"模型说的 30% 概率，是不是真的有 30% 的人会买？" 如果模型说"20% 会买"的群体实际有 18% 买了，那模型就是**可靠**的；如果实际只有 2% 买了，那模型的概率数字就是"虚高"，不能直接当"购买意向度"用。

### 怎么读图

- 横轴 = 模型预测概率（对数轴，因为概率都集中在 0~5% 的低位）
- 纵轴 = 该区间里真实的购买比例
- 灰色对角线 = 完美校准（说多少就是多少）

### 背后的算法逻辑

把 46 万个预测概率按大小分箱（0~0.5%、0.5%~1%、1%~2%、2%~5%……），每箱至少 30 个样本，然后对比"箱内平均预测概率" vs "箱内真实购买率"。

**为什么要用对数轴？** 这个模型的预测概率几乎全部挤在 0~2% 的区间（正样本太少，模型很少给出高概率），如果线性画，所有点都会挤在左下角，什么都看不出来。对数轴把低概率区间"放大"了。

### 当前数据的结论

低概率区间的点会偏离对角线（由于稀疏正样本的噪声），但整体趋势贴近。看板里的解读要点是：**在极不平衡场景下，更应关注概率的相对排序（谁比谁高），而不是绝对值**。

### 业务含义

这张图回答"概率能不能当分数用"——**如果未来要做"购买意向分层"（比如概率>5% 是高意向、1~5% 是中意向），需要这张图证明概率数字可信**。当前结论：排序可信，绝对值需谨慎。

# 模块三 · 分人群体检：多维度分群性能拆解

## 3.1 Top-K 推荐效果（Precision@K / Recall@K / MAP@K）

### 这张图回答什么业务问题

这是**整块看板最接近"业务落地"的一张图**。前面所有指标都是"对 46 万对逐个打分"，但真实推荐系统的动作是：**每个用户，只推 10 个商品**。Top-K 就是回答："如果我每个用户只给 K 个坑位，模型能放对几个？"

### 怎么读图

- 横轴 K = 给每个用户推荐的坑位数（5/10/20/30/50）
- 红线 Precision@K = 推出去的里面，有几个真买了
- 蓝线 Recall@K = 所有真实购买里，被 Top-K 覆盖了多少
- 绿线 MAP@K = 把"买到的位置"也考虑进去（买到越靠前越好）

### 背后的算法逻辑

**三个指标各自回答一个问题：**

- **Precision@K**："推 100 个，中几个？"——衡量**推送的纯度**（打扰多不多）
- **Recall@K**："所有买家里，Top-K 捞到几个？"——衡量**覆盖的广度**（漏单多不多）
- **MAP@K**："买到的商品排在第几位？"——衡量**排序的质量**（第一屏能不能就推中，比第 48 位才推中强得多）

**MAP 为什么比 P@K/R@K 更严格？** 假设给用户推 10 个，9 个没买、第 10 个买了——P@10=10%，R@10=100%。但用户根本滑不到第 10 位。MAP 会惩罚这种"买到了但位置太靠后"的情况。**业务上位置=曝光=收入，所以 MAP 更贴近真实收益。**

**当前数据（测试集实测）**：

| K | P@K | R@K | 业务解读 |
|---|---|---|---|
| 5 | 0.82% | 81.5% | 每个用户推 5 个，就能覆盖 8 成买家 |
| 10 | ~0.7% | 93.5% | 推 10 个，覆盖 9 成以上买家 |
| 50 | 更低 | ~100% | 推得越多覆盖越全，但纯度下降 |

### 业务含义

这是全看板最亮眼的数字：**"每个用户只推 10 个商品，就能覆盖 93.5% 的真实购买行为"**——而随机推 10 个，覆盖不到 1%。这句话可以直接进汇报结论。它证明了：虽然整体精确率只有 11.8%，但**在"每用户 Top-K"的真实业务形态下，模型的排序价值被充分兑现**。

## 3.2 用户分层性能对比

### 这张图回答什么业务问题

"模型对**谁**好用？" 把用户分成超级用户/普通用户、低/中/高活跃度，看模型在每类人身上的表现。回答："**我该信任这个模型对哪些用户的判断？**"

### 怎么读图

- 蓝柱 = 该类用户的 ROC-AUC（排序能力）
- 红线 = 该类用户的召回率（能逮到多少买家）
- 悬停可见该群体样本数、正样本数

### 背后的算法逻辑

用 `user_pv_count` 四分位 + `is_power_user` 标志把用户分组，每组单独算一遍 ROC-AUC 和召回率。**分组的意义在于：模型在 A 类用户上好用，不代表在 B 类用户上也灵**——特征在不同群体里"信号强度"不同。

### 当前数据的结论

超级用户、高活跃用户的召回率明显更高——因为他们行为丰富，特征信号足；低活跃用户行为稀疏，模型可用的信息少，召回率掉下来。**这正是模块五"冷启动短板"的伏笔**（前后呼应，体现分析的连贯性）。

### 业务含义

**分层决策**：高活跃用户可以直接用模型推荐（信号足、可信）；低活跃用户应降权或搭配其他策略（如热门兜底）。看板给出的是"哪些用户群可以放心用"的地图。

---

## 3.3 商品分层性能对比

### 这张图回答什么业务问题

同用户分层，只是换到**商品侧**："模型对**哪些商品**的判断靠谱？" 爆款、腰部、长尾三类商品分开评估。

### 怎么读图

同 3.2：蓝柱 = 该层级商品的 ROC-AUC，红线 = 召回率。

### 背后的算法逻辑

按 `item_pv_count` 三分位切分（爆款 Top 1/3、腰部、长尾 Bottom 1/3）。**长尾商品尤其值得关注**：推荐系统最常见的痛点就是"只会推爆款，长尾商品没人看"。

### 当前数据的结论

长尾商品的指标反而保持不错（模块五数据：长尾商品 F1=0.363，比整体 0.192 还高，召回率 74.2%！）——**"模型不仅会推爆款，还能在长尾商品上精准命中"**，这是一个反直觉的亮点：因为长尾商品交互数据少，能识别出来反而说明模型从"类目/用户偏好"等特征学到了泛化能力，而非死记热度。

### 业务含义

**长尾商品是电商利润的重要来源**（爆款利润薄、竞争激烈）。模型在长尾上的表现证明它可以用于"千人千面的长尾推荐"，而不是只会追爆款——这是对业务价值的直接加分项。

## 3.4 时间维度稳定性（每日 ROC-AUC + 召回率）

### 这张图回答什么业务问题

"模型是不是**昨天好用、今天失灵**？" 把测试集按天拆开，每天单独算 AUC 和召回率，看 31 天（2025-11-18 ~ 12-18）的表现有没有波动，尤其是**双 12 大促当天**（橙色高亮区）。

### 怎么读图

- 蓝线 = 每日 ROC-AUC（稳定在 0.98 上下为佳）
- 红线 = 每日召回率
- 橙色阴影 = 双 12 大促日，检验"大促这种极端场景模型还能不能用"

### 背后的算法逻辑

按 `last_time` 的日期分组，每天单独算指标。**为什么要单独看大促？** 大促日行为模式剧变（大量集中浏览、冲动购买），如果模型在大促日崩溃，线上就要准备预案。

### 当前数据的结论

AUC 日间稳定（均值 0.98+，标准差很小），双 12 当天没有明显塌陷；召回率日间波动大一些——但**每日正样本只有 5~45 个，召回率的小幅波动主要是"样本太少"的统计噪声，不是模型退化**。看板里这句"先看 AUC 稳定性，再看召回率噪声"是很好的严谨表达。

### 业务含义

**"模型在 31 天、含大促的完整周期内表现稳定"**——这证明模型不是"只在某个时段灵光"，可以放心上线。时间稳定性是评审最常追问的点之一（"你的模型会不会过两天就废了？"），这张图直接给出答案。

# 模块四 · 让模型自述理由：特征可解释性

## 4.1 SHAP 蜂群图（Top 10 特征重要性）

### 这张图回答什么业务问题

前面所有图都在说"模型表现如何"，这张图开始说"**模型凭什么这么判断**"。蜂群图一次性给三重信息：

1. **重要性**：哪些特征对模型决策影响最大（从上到下排序）
2. **方向**：特征往右推=推向"购买"，往左=推向"不购买"
3. **规律**：红点（特征值高）往哪边跑——**特征值高是促进还是抑制购买**

### 怎么读图

- 纵轴：Top 10 特征，越靠上越重要
- 横轴：SHAP 值，0 是中轴线，**右=推向购买，左=推向不购买**
- 颜色：特征值高低（红=高，蓝=低，标准化后 0 表示全体均值）
- 每个点 = 一条测试样本；点的横向位置 = 该特征对这条样本的"推/拉"力度

### 背后的算法逻辑

**SHAP 是什么（白话版）**：把"模型的预测"拆成"每个特征各贡献了多少分"。比如模型预测某个用户会买，SHAP 能告诉你：是"这个商品被买过 500 次"贡献了 +2.0 分，"用户最近 3 天没来"贡献了 -0.5 分……所有特征加起来 = 最终预测。

**log-odds 空间是什么意思**：SHAP 的分数不是概率，是"对数几率"。正分推高概率，负分压低概率。蜂群图的横轴单位是"贡献分"，不是概率——所以图中说"右=推向购买"。

**为什么图里点是"一列一列"堆叠的？** 真实的 SHAP 值在横轴上是连续分布的，但如果直接画点，几万条样本会糊成一团。蜂群图给每个点加一点**随机抖动（jitter）**，让重叠的点散开，看起来像"蜜蜂群"——**抖动只影响视觉位置，不影响真实 SHAP 值**（悬停能看到真实数值）。

### 当前数据的结论

Top 特征全是"商品热度 + 用户偏好"类：

| 排名 | 特征 | 业务解读 |
|---|---|---|
| 1 | 商品购买数（item_buy_count） | **"买得多=还会买"**——被验证过的商品更可信 |
| 2 | 用户类目偏好分 | **"用户在这个类目逛得越多，越可能买"** |
| 3 | 商品购买人数 | 从众效应：很多人买，说明商品靠谱 |
| 4 | 商品浏览→购买率 | 转化率高的商品，是"真热门"而非"虚火" |
| 5 | 用户购买转化率 | 用户本身的购买习惯 |

### 业务含义

**模型"讲道理"**——它学到的规律和商业直觉一致：被买得多的商品、用户偏好的类目、转化率高的商品，确实更容易被买。这对业务方的说服力极强："**模型不是黑盒，它的决策逻辑我们可以解释，而且解释得通。**"

---

## 4.2 SHAP 依赖图（Top 3 特征）

### 这张图回答什么业务问题

蜂群图只说了"这个特征重要"，依赖图进一步说："**这个特征的影响是怎么变化的？**" 它要挖出**非线性规律**：是不是特征值越高越好？还是到某个值就"饱和"了？

### 怎么读图

- 横轴：特征值（标准化）
- 纵轴：SHAP 贡献值
- 每个点 = 一条样本
- 灰色虚线 = 0 轴（上方=促进购买，下方=抑制购买）
- 三个子图 = 最重要的三个特征

### 背后的算法逻辑

**为什么"斜率"值得看？** 线性模型里"特征每涨 1 个单位，贡献固定涨多少"；但 XGBoost 是树模型，特征的影响可能是**阶梯形、饱和形、甚至 U 形**：

- 陡峭上升 → 这个特征很"敏感"，值一高就强推购买
- 到顶后走平 → **饱和效应**：特征值再高也没用了（比如商品购买数超过一定量后，"再买一次"的概率不再上升）
- 0 轴附近徘徊 → 该特征对多数样本影响小

### 当前数据的结论

以"商品购买数"为例，依赖图会显示：购买数低时贡献为负（冷门商品，模型倾向不推），随购买数上升贡献迅速转正，到一定程度后趋于饱和——**"头部商品和腰部商品的购买概率差距，没有腰部到长尾的差距大"**。

### 业务含义

**饱和点就是运营抓手**：找到"特征值到多少贡献不再增加"，就知道"再堆多少流量/评价/库存对转化没有边际收益"。如果汇报被问到"模型有没有发现什么反直觉规律"，依赖图的非线性形状就是最好的素材。

## 4.3 典型样本局部解释（瀑布图：TP / FP / FN）

### 这张图回答什么业务问题

前面都是"对全体样本的解释"，瀑布图是"**对单独一个人的解释**"。它回答："为什么这个具体用户、这个具体商品，模型给出了这个预测？" 三个页签分别展示三种典型：

- ✅ **自信命中 TP**：模型高概率判"买"，且真的买了——"模型为什么看对了"
- ⚠️ **自信误判 FP**：模型高概率判"买"，但实际没买——"模型为什么看走眼"
- ❌ **严重漏判 FN**：模型低概率判"不买"，但实际买了——"模型为什么漏了"

### 怎么读图

- 起点 = 基准值（bias，所有样本的共同起点）
- 每一级 = 一个特征把预测"推高"（红色上升）或"拉低"（蓝色下降）多少
- 终点 = 最终预测 logit（可换算成概率）

### 背后的算法逻辑

瀑布图是 SHAP **可加性**的直接可视化：`最终预测 = bias + 特征1贡献 + 特征2贡献 + …`。这是模块四里最"算法硬核"的一张图——**"为什么瀑布图能画？因为 SHAP 值满足可加性，把每个特征的贡献当成砖头一块块垒起来，最终垒成预测结果"**。

**为什么选 TP/FP/FN 三个典型样本而不是随机样本？** 随机样本没有教学意义。看"模型最自信的命中"能展示模型捕捉到了什么强信号；看"最自信的误判"能定位模型被什么假信号骗了；看"最严重的漏判"能发现模型缺了什么信息。

### 当前数据的结论

- TP 样本：大概率是"商品购买数 + 类目偏好分"同时拉满，模型据此高置信判买
- FP 样本：通常是"环境特征看起来很热"（商品热、类目热、用户购买力强）但**用户自身近期活跃度低**——"看着会买，其实不会"
- FN 样本：用户低活跃 + 交互稀疏，但实际买了——**"模型没看到足够证据"**

### 业务含义

瀑布图是**"可解释 AI"的展示核心**——评审/业务方可以直接看懂"为什么推给我这个商品"。未来如果要做"推荐理由"（"因为您常逛数码类目，且这款商品近期热度高"），瀑布图就是推荐理由的算法原型。

## 4.4 正负向影响特征汇总

### 这张图回答什么业务问题

"**哪些特征在把模型推向'买'，哪些在推向'不买'？**" 一张图给出"买入逻辑"和"不买逻辑"的全局清单。

### 怎么读图

- 横轴 = 正样本平均 SHAP − 负样本平均 SHAP（正负标签的贡献差）
- 红条（正值）= 在真实购买样本上更推高预测 → **"购买信号"**
- 蓝条（负值）= 在未购买样本上更推低预测 → **"不买信号"**
- 0 线 = 分界

### 背后的算法逻辑

把样本按真实标签分组：计算每个特征在"真买的人"身上的平均贡献，减去在"真没买的人"身上的平均贡献。**差值越大，说明这个特征越是"购买的决定性差异"**——它不只是重要，而且是"买与不买之间最显著的区分点"。

### 当前数据的结论

正向榜首是**商品购买数、用户类目偏好分、商品购买人数**（差值 +5.02 / +2.72 / +2.19）——**"商品的热度 + 用户的偏好 = 购买的核心驱动"**。值得注意 `repurchase_item_count`（用户复购商品数）差值为负——**复购多的用户反而不容易被模型推高**，可能是这类用户购买行为更随机/更分散。

### 业务含义

这张图不需要算法基础就能看懂，是**给业务方/非技术评审看的"结论页"**：模型认为"什么信号说明要买"（热销+偏好）、"什么信号说明不买"，可以直接转化为运营策略（比如对"类目偏好强"的用户重点推该类目）。

# 模块五 · 认错与复盘：错误分析与模型边界

## 5.1 错误样本画像对比（FP / FN 特征画像）

### 这张图回答什么业务问题

"**模型犯的错，有没有规律？**" 把所有 FP（预测买、实际没买）和 FN（预测没买、实际买了）拿出来，看它们在特征上"长什么样"——是随机犯错，还是**系统性地被某些特征误导**？

### 怎么读图

- 橙色条 = FP 群体在某特征上的标准化均值
- 蓝色条 = FN 群体
- 0 = 全体均值水平；正值 = 该群体在这个特征上明显高于全体

### 背后的算法逻辑

标准化均值对比：把 FP 样本、FN 样本分别算特征均值，再和全体均值比。**"画像"就是"平均长相"**——如果某特征均值偏离 0 很远，说明这类错误样本在"长"得像某个类型。

### 当前数据的结论（真实数字，很有故事性）

**FN（漏判）画像：**
- 商品购买数 +1.57、商品购买人数 +1.63、用户购买转化率 +1.45、类目偏好 +1.08——**全是"高热度、高购买力"信号**
- 但用户浏览数 **-0.21**——**用户自身活跃度反而低于平均**

**FP（误判）画像：**
- 商品购买数 +1.11、购买人数 +1.27、转化率 +1.59、RFM-F +0.71——**"环境看起来非常热"**
- 用户浏览数 **-0.25**——同样用户活跃度低

**共同规律：模型被"商品热度和用户购买力"这类环境信号牵着走，但用户自己的近期活跃度（浏览数）低，模型就判错了。** 换句话说：**"一个不怎么活跃的人，突然对一个很热的商品表现出购买意图"——模型分不清这是真买还是偶然。**

### 业务含义

错误不是随机的，是有画像的——**这本身就是分析能力的体现**。落地方向：给"低活跃用户 × 高热度商品"的组合降权，或者补充用户近期活跃特征。评审听到"我们分析了错误样本，发现它们不是随机噪声而是有系统性模式"——这是加分项。

---

## 5.2 冷启动与长尾场景专项对比

### 这张图回答什么业务问题

推荐系统有两大行业级难题：**冷启动**（新用户/新商品没有历史数据）和**长尾**（小众商品曝光少）。这张图回答："**我们的模型，在这两个公认的难点上表现如何？**"

### 怎么读图

- 左图：三类场景的 ROC-AUC
- 右图：三类场景的召回率 / F1
- 三类 = 整体 / 冷启动用户（活跃度 Bottom 20%）/ 长尾商品（热度 Bottom 20%）

### 背后的算法逻辑

- **冷启动用户** = 行为最稀疏的 20% 用户。他们的特征大多是"0/很低"，模型可用的信号极少
- **长尾商品** = 热度最低的 20% 商品，同理特征稀疏
- 分别在这些子集上评估，与整体对比

### 当前数据的结论（真实数字）

| 场景 | 样本数 | 正样本 | ROC-AUC | PR-AUC | 召回率 | F1 |
|---|---|---|---|---|---|---|
| **整体** | 468,316 | 449 | 0.9942 | 0.1312 | 51.2% | 0.192 |
| **冷启动用户** | 15,145 | 33 | 0.9821 | 0.0692 | **15.2%** | **0.085** |
| **长尾商品** | 80,876 | 89 | 0.9983 | 0.2523 | **74.2%** | **0.363** |

两个结论都很"有料"：

1. **冷启动用户是明确短板**：F1 只有整体的一半（0.085 vs 0.192），召回率 15.2% vs 51.2%——**"没数据，模型就失灵"**，这是所有推荐系统的共性难题
2. **长尾商品反而超常发挥**：F1 0.363 比整体还高 89%，召回率 74.2%——**模型在稀疏商品上依然精准**（结合 3.3 商品分层，前后印证）

### 业务含义

**主动暴露短板 + 给出方向 = 专业的表达**：

- "我们清楚冷启动是短板（F1 0.085），这是行业共性难题，优化方向是补充新用户特征（注册时长、首日行为）和内容相似度召回"
- "长尾商品表现优秀（F1 0.363），说明模型可用于千人千面的长尾推荐，这是利润点"

**主动说"我知道哪里不行"比被追问出来，可信度高一档。**

## 5.3 高置信误判样本明细（Top 错误表）

### 这张图回答什么业务问题

画像告诉我们"错误群体平均长什么样"，明细表则展示"**单个错误案例长什么样**"——让抽象结论落到具体样本上，方便逐案归因。

### 怎么读图

- 可切换 FP / FN 两类错误
- 按预测置信度排序：FP 看"模型最自信却错了"的；FN 看"模型最该逮到却漏了"的
- 每行展示该样本的用户、商品、预测概率及关键特征值

### 背后的算法逻辑

从全量错误样本中取"最极端"的 20 条——**置信度最高的误判**是最值得分析的：模型"非常确定"却错了，说明模型抓到了某种强但错误的信号；**置信度最低的漏判**说明模型完全没接收到该买的信号。

### 当前数据的结论

与 5.1 画像相互印证：高置信 FP 多为"高热度商品 + 高购买力用户 + 低活跃度"的组合——**模型被环境信号误导**；严重 FN 多为"低活跃用户"——**模型信息不足**。

### 业务含义

明细表是"**可审计性**"的证明——"我们不只给你看统计结论，还把具体错误样本摊开给你看"。如果未来做模型迭代，这些表格就是第一批人工复核样本。
